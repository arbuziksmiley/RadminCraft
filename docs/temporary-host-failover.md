# Временный Host

## Принятое продуктовое решение

Одна установленная копия RadminCraft настраивается для одного сообщества.
Поддержка одновременной работы в нескольких сетях Radmin VPN сейчас не нужна.
Внутренний `communityId` остаётся: он не показывается пользователю и не является
«профилем второй сети», а защищает перенос от смешивания чужих снимков.

## Что реализовано

- основной Host выдаёт подписанный Ed25519 снимок сообщества;
- снимок содержит `communityId`, основной адрес, `deviceId` владельца, эпоху и
  упорядоченный список доступных кандидатов;
- клиент доверяет ключу основного Host при первом подключении (TOFU) и отвергает
  подмену ключа, подписи или откат эпохи;
- актуальная история чата и реестр участников кэшируются у клиентов;
- после 15 секунд недоступности основного Host первый кандидат становится
  временным; следующие кандидаты получают окна через 5 секунд и сначала
  проверяют более приоритетных;
- временный Host обслуживает общий чат, presence, приглашения и WebRTC
  signaling; голосовой трафик по-прежнему идёт напрямую между участниками;
- клиенты продолжают проверять основной Host в фоне, не задерживая чат и голос;
- вернувшийся основной Host принимает недостающие сообщения и участников,
  повышает эпоху и снова становится единственным основным Host;
- незавершённое восстановление сохраняется на диск и повторяется после
  перезапуска временного компьютера;
- интерфейс показывает «Временный Host», а во вкладке Host есть общий
  выключатель функции.

## Что намеренно не переносится

Minecraft-сервер, BlueMap, чтение `latest.log` и серверные инструменты физически
остаются на основном компьютере. Пока он выключен, временный Host сохраняет
общение, но не имитирует работу игрового сервера.

## Логика интерфейса и прав

Используется одна общая сборка RadminCraft, но интерфейс зависит от локальной
роли и текущего состояния сети:

- основной Host видит во вкладке `Host` один общий переключатель сохранения
  связи при его отключении;
- обычный участник видит в `Подключении` только готовность своего компьютера
  стать кандидатом на роль временного Host;
- основной Host не видит настройку кандидатуры собственного компьютера;
- после повышения участник сохраняет роль обычного участника и не получает
  настройки владельца, очистку общего чата, Minecraft Bridge или BlueMap;
- пока компьютер обслуживает сообщество как временный Host, переключатель
  кандидатуры заменяется информационным статусом;
- после возвращения основного Host участник автоматически возвращается в
  обычное состояние, сохраняя прежнюю готовность быть резервным.

Таким образом, два переключателя относятся к разным уровням: владелец разрешает
резервирование для сообщества, а участник разрешает использовать конкретный
компьютер. На одном экране и у одной роли они одновременно не показываются.

## Ограничения первой реализации

- всем участникам нужна одна и та же свежая версия RadminCraft;
- кандидат должен оставаться включённым и иметь доступный TCP-порт `18483`;
  при первой подготовке Windows может запросить разрешение UAC для правила
  брандмауэра;
- при полном разделении Radmin VPN на две изолированные группы невозможно
  математически гарантировать отсутствие двух временных Host без внешнего
  координатора. Подписанный снимок, детерминированный порядок, временные окна и
  приоритет вернувшегося основного Host уменьшают этот риск;
- голосовой разговор переживает переключение signaling-сервера, но уже
  установленные WebRTC-соединения зависят от состояния клиентов; при сетевом
  разрыве они переподключаются обычным механизмом голосового канала.

## Проверки

Чистая логика находится в `electron/failover.js`, тесты — в
`tests/failover.test.js`. Проверяются нормализация Radmin-адресов,
детерминированный выбор, временные окна, подпись и обнаружение подмены снимка.
